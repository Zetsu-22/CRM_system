## Backend / Orders

### ORD-002 — `PUT /orders/{id}` падает с 409 при первом же обновлении ✅ FIXED 2026-05-09
**Симптом:** обновление заказа сразу возвращает `409 concurrency_conflict` для `SalesOrderLine`.

**Корень:** `RowVersion` у `SalesOrder/SalesOrderLine` отключён (`Ignore`), но `OrdersController.Update` помечал старые строки `IsDeleted=true` (`Modified`) и добавлял новые. EF при `SaveChangesAsync` мог получить 0 затронутых строк для `UPDATE` (если строка уже была soft-deleted предыдущей неудачной попыткой) → `DbUpdateConcurrencyException`.

**Фикс:** `OrdersController.Update` теперь делает hard-delete старых строк (`db.OrderLines.RemoveRange`) и добавляет новые. См. коммит/diff в `CrmSystem.Api/Controllers/OrdersController.cs`.

**Acceptance проверить:**
- Изменение комментария/qty/unitPrice заказа в одном клиенте даёт 200 OK. ⏳ ожидает прогона.
- Параллельное изменение в двух вкладках корректно вернёт 409 — будет работать после **фазы 1.9** (реальный concurrency-токен).

### ORD-003 — НДС-режим не влияет на расчёт (P1)
**Симптом:** переключатель «НДС в сумме / сверху» в форме заказа не меняет итог, всегда считается одинаково (фактически «сверху»).

**Где чинить:** фаза **6.4 (режимы НДС)**.

---

### ORD-004 — Для UI логика «достаточности склада» не нужна (P1, scope)
В прототипе `new-fimbiz-react` нет складов/остатков. Нужно убрать `WarehouseId`, `Stock`, `availableQty`, `Manufacturing` из API/UI/доменной модели.

**Где чинить:** обновлённая **фаза 1.x** (см. план), миграция со сносом `Warehouses`/`StockBalance`/`StockMovement`.

## Frontend / UX

### UX-001 — Setup Company открывается отдельной страницей вместо модалки (P2)
**Симптом:** на странице «Компании» нажатие «Создать компанию» уводит на отдельный layout, похожий на login.

**Ожидание:** модалка на той же странице, после создания компания появляется в списке.

**Где чинить:** фаза **5.4 / 6.5** (UI-полировка).

---

### UX-002 — Setup Company валидирует только `companyName` (P1)
**Симптом:** компания создаётся при заполнении только названия. На бэке нет валидации, на фронте нет полей (ИНН, КПП, ОГРН, юр. адрес и т.п.).

**Ожидание:** обязательные поля компании-владельца как минимум по аналогии с `Counterparty` (ИНН/КПП/ОГРН/полное наименование/юр.адрес).

**Где чинить:** фаза **1.5 (FluentValidation)** на бэке + фаза **5.3 (zod)** на фронте.

---

### UX-003 — Чекбокс «По умолчанию» в форме Organization без объяснения (P2)
**Симптом:** в модалке создания организации есть чекбокс `isDefault` без подсказки.

**Ожидание:** убрать или дать tooltip («Использовать как организацию по умолчанию для новых документов»).

**Где чинить:** фаза **5.4** (UI).

---

### UX-004 — Модалки закрываются по клику за пределами без подтверждения (P1)
**Симптом:** при заполнении формы (особенно Counterparty) случайный клик закрывает модалку и вся форма теряется.

**Ожидание:** клик вне модалки = подтверждение «Закрыть без сохранения?», либо вообще не закрывать модалку, только по кнопке.

**Где чинить:** фаза **5.4** — общий компонент `<Modal>` с настройкой `closeOnBackdropClick=false` или `confirmOnDirty`.

---

### UX-005 — Нет подсказок длины ИНН/КПП/ОГРН (P2)
**Ожидание:** в `placeholder` или подсказке указать ожидаемый формат (10/12 цифр, 9 цифр и т.п.) — не как text который надо стирать.

**Где чинить:** фаза **5.3 / 5.4**.

---

### UX-006 — Страница создания заказа неудобная (P0 для UX)
**Симптомы:**
- Нет поиска номенклатуры при добавлении строки.
- Нет поиска контрагента.
- Скидка разделена на «процент / сумма» — нужен только процент (как в `new-fimbiz-react`).
- После создания заказа модалка закрывается, вместо открытия созданного заказа.
- При редактировании суммы позиции (qty/unitPrice) сумма строки всегда `0`, пересчитывается только итог справа.

**Ожидание:**
- Поиск контрагента и номенклатуры (autocomplete).
- Только процентная скидка.
- После `POST` открывать созданный заказ.
- Сумма позиции = `qty * unitPrice * (1 - discount%)` (с учётом VAT-режима).

**Где чинить:** фаза **5** (`OrderUpsertPanel`) + сверка с `new-fimbiz-react` для логики скидок (см. memory о ролях/прототипе).

## Auth / Tenant

### AUTH-001 — При `switch-company` с `companyId=null` сохраняются права компании (P2)
**Симптом:** в response `switch-company { companyId: null }` поле `companyId=null`, но флаги `isAccessOrdersEdit/Picker/Driver/...` остаются `true` (как для роли владельца).

**Ожидание:** для «Личного» профиля (без компании) — сбрасывать все access-флаги в `false`.

**Где чинить:** фаза **2.4 (Permissions)** — права должны зависеть от текущего профиля, а не от пользователя.
