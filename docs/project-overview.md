# CRM_system — описание проекта

## 1. Назначение

Внутренняя CRM‑система для управления:

- **Заказами** (SalesOrder) — полный цикл от черновика до получения
- **Контрагентами** — клиенты/поставщики с реквизитами
- **Номенклатурой** — товары и услуги
- **Складами и остатками** — учёт количества товара на складе
- **Документами** — счета (Invoice) и УПД (Upd)
- **Платежами** — входящие/исходящие платежи со статусами

**Стек:**
- Backend: ASP.NET Core + EF Core + PostgreSQL
- Frontend: React + TypeScript + Vite


## 2. Структура репозитория

```
CRM_system/
├── CrmSystem.Api/          # Web API (.NET)
│   └── Controllers/        # REST-контроллеры
├── CrmSystem.Domain/       # Доменные сущности и enum'ы
├── CrmSystem.Persistence/  # EF Core контексты и миграции
├── crm-web/                # React SPA
│   └── src/pages/          # Страницы UI
├── docs/                   # Документация
├── docker-compose.yml      # PostgreSQL для разработки
└── run.ps1                 # Скрипт запуска (сборка + миграции + старт)
```


## 3. Запуск

```powershell
./run.ps1
```

Скрипт:
1. Поднимает PostgreSQL (Docker или локальный)
2. Применяет миграции EF Core
3. Запускает backend (`http://localhost:5035`) и frontend (Vite, обычно `http://localhost:5173`)

## 5. Сущности (Domain)

### Company
Компания‑владелец всех данных.
- Название, ИНН, КПП, ОГРН
- Юр./факт. адрес
- Банковские реквизиты
- Плательщик НДС (да/нет)

### Organization
Подразделение внутри компании.
- Название, адрес, флаг «по умолчанию»

### Counterparty
Контрагент (клиент или поставщик).
- Тип: `Customer` / `Supplier` / `Both`
- Статус: `Active` / `Blocked`
- Реквизиты: ИНН, КПП, ОГРН
- Срок оплаты (дней)

> **Примечание:** В домене есть сущности `CounterpartyAddress` и `CounterpartyContact`, но в текущем UI они **не используются** — контрагент редактируется без адресов и контактов.

### Item (Номенклатура)
- Тип: `Product` / `Service`
- Артикул (SKU), штрихкод
- Название, ед. измерения
- Ставка НДС: 0% / 5% / 7% / 10% / 22%
- Складской товар (да/нет)


### StockBalance (Остатки)
Остаток товара на складе.
- `QtyOnHand` — количество на складе

> **Примечание:** В домене есть поле `QtyReserved`, но в текущей бизнес‑логике **резервирование не реализовано**. UI показывает только `QtyOnHand` как «Остаток».

### SalesOrder (Заказ)
- Номер, дата
- Компания, контрагент
- Статус (см. ниже)
- Суммы: без НДС, НДС, итого
- Комментарий
- Флаг `IsAssemblyChecklistClosed`
- Позиции (`SalesOrderLine`)

### SalesOrderLine
- Товар (`ItemId`)
- Снапшоты: название и ставка НДС на момент создания
- Количество, цена за единицу
- Скидка: тип (`None`/`Percent`/`Amount`) + значение
- Суммы: без НДС, НДС, итого

### Invoice (Счёт)
- Номер, дата, статус
- Связь с заказом (опционально)
- Позиции, суммы
- `PaidAmount` — сколько оплачено

### Upd (УПД)
- Номер, дата, функция, статус
- Связь с заказом/счётом
- Дата отгрузки
- Позиции, суммы

### Payment (Платёж)
- Тип: `Incoming` / `Outgoing`
- Дата, сумма
- Метод: `Bank` / `Cash` / `Card`
- Статус: `Draft` / `Posted` / `Cancelled`
- Номер п/п, внешний ID

> **Примечание:** В домене есть `PaymentAllocation` для распределения платежа по счетам, но в UI это **не реализовано**.


## 6. Статусы заказа

Полная схема — в `docs/order-status-lifecycle.md`.

Краткий список:

| Код | Статус | Описание |
|-----|--------|----------|
| 0 | Draft | Черновик |
| 1 | Processing | Обрабатывается |
| 2 | WaitingForPayment | Ожидает оплаты |
| 3 | BillConfirmed | Счёт подтверждён |
| 4 | Manufacturing | Изготавливается |
| 5 | Picking | Собирается |
| 6 | TransferredToTransport | Передан в ТК |
| 7 | DeliveringByTransport | Доставляется ТК |
| 8 | Delivering | Доставляется |
| 9 | AwaitingPickup | Готов к получению |
| 10 | Completed | Получен |
| 11 | Cancelled | Отменён |

**Особенность:** статус `Manufacturing` появляется только если на складе недостаточно товара для выполнения заказа.


## 7. Роли и права

Права проверяются и в UI, и в API.

| Роль | Флаг профиля | Возможности |
|------|--------------|-------------|
| Владелец | `isCompanyOwner` / `isBasicProfile` | Полный доступ |
| Редактор заказов | `isAccessOrdersEdit` | Создание/редактирование заказов |
| Сборщик | `isOrderPicker` | Только закрытие чеклиста сборки |
| Водитель | `isDriver` | Только просмотр заказов |
| Экспедитор | `isExpeditor` | Доступ как у редактора |


## 8. API (основные эндпоинты)

Base: `/api/v1`

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/orders` | Список заказов |
| GET | `/orders/{id}` | Детали заказа |
| POST | `/orders` | Создать заказ |
| PUT | `/orders/{id}` | Обновить заказ |
| DELETE | `/orders/{id}` | Удалить заказ |
| POST | `/orders/{id}/confirm` | Подтвердить (Draft → Processing) |
| POST | `/orders/{id}/next-status` | Следующий статус |
| POST | `/orders/{id}/cancel` | Отменить |
| POST | `/orders/{id}/assembly-checklist/close` | Закрыть чеклист сборки |

Аналогично для: `/companies`, `/organizations`, `/counterparties`, `/items`, `/warehouses`, `/invoices`, `/upds`, `/payments`

## 10. Что НЕ реализовано (есть в домене, но не в UI)

- **Адреса и контакты контрагентов** — сущности есть, UI нет
- **Резервирование товара** (`QtyReserved`) — поле есть, логика не используется
- **Распределение платежей по счетам** (`PaymentAllocation`) — сущность есть, UI нет
- **Движения остатков** (`StockMovement`) — сущность есть, не используется
